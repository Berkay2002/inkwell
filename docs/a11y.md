# Accessibility

Engine: `src-tauri/src/a11y/`. It does what Acrobat's Accessibility checker and Autotag do. The check reads the document as it is now, unsaved edits included, from its own copy of the current generation, so it never holds the edit lane. Each fix is one edit-core step: it can be undone, Save keeps it, and history records it. Tests are in `a11y/tests.rs`. They use generated PDFs, with a pass and a fail case per rule, and every fix survives save and reopen.

## Commands

- `a11y_check(job, doc, onProgress) -> Report` runs off the UI thread. `onProgress` gets `{done, pages, stage}` once per page scanned (`stage` is `check`). `job` is an id the UI picks: `tool_cancel(job)` stops the check between pages, and the promise rejects with `cancelled`.
  `Report = {pages, tagged, certified, signed, results: [{rule, name, group, status, hint, fix, findings: [{page, object, xref, rect, message}]}]}`.
  - `rule` is the stable id from the table below.
  - `group` is Acrobat's category: Document, Page content, Forms, Alternate text, Tables, Lists or Headings.
  - `rect` is `[x0, y0, x1, y1]` in page points from the top left (the viewer's page space), or null. Annotations (links, fields) have their `/Rect`; elements have the bounds of their marked content (images, form XObjects, painted paths). Text has no extent here, so a text-only element has no `rect` and "Show" goes to its page.
  - `status` is `passed`, `failed`, `manual` (needs a manual check) or `skipped` (the rule doesn't apply).
  - `page` is 0-based.
  - `xref` is the object number, when the object is an indirect PDF object.
  - `fix` names the automatic fix, when there is one.
  - A rule shows at most 200 findings, then "... and n more".
- `a11y_fix(job, doc, fix, onProgress) -> EditState` applies one fix as one undo step. Autotag reports `{done, pages, stage}` per page (`read`: the text of every page, to find the body size; then `tag`), and `tool_cancel(job)` ends it with `cancelled`, leaving the document as it was and adding no step. `{"fix": "many", "fixes": [...]}` is "Fix all safe issues": the simple fixes in one step; each with nothing to do is skipped, and the step is refused only when none applied. Examples: `{"fix": "title", "title": "..."}` (title is optional), `{"fix": "language", "lang": "en-US"}`, `{"fix": "displayDocTitle"}`, `{"fix": "tabOrder"}`, `{"fix": "fieldTooltips"}`, `{"fix": "figureAlt", "xref": 12, "alt": "..."}`, `{"fix": "autotag"}`. A fix with nothing to do is refused and adds no step: tab order already set, no field missing a tooltip, a bad language tag, or an `xref` that isn't a Figure element.

- `a11y_preview(doc) -> {untagged, pages, figures, links, fields}` says what Autotag would do, counted from the file, so the UI can state the outcome before it runs.
- `a11y_export_report(job, doc, format, date, to, onProgress) -> path` checks the document again and writes the report to the file of save token `to` (from `pick_save`; `format` is `html` or `pdf`, `date` the display text for the header). The HTML has Acrobat's shape: a summary, then a table per group with the findings and their pages; the PDF has the same content and is written with the comparison report's writer. The command refuses a target that is an open document (`check_not_open`), as does the comparison report's export.

- **Reading order and tags** (see "Reading order and tags" below): `a11y_reading_order(doc, page)`, `a11y_tags(doc, page?)`, `a11y_tag_problems(doc)`, and the edits `a11y_reorder`, `a11y_set_role`, `a11y_artifact`, `a11y_merge_regions`, `a11y_merge_many`, `a11y_split_region`, `a11y_edit_tag`, `a11y_move_tag`. Each edit is one undo step, kept by Save.
- Two more `a11y_fix` fixes: `{"fix": "metadata"}` (XMP title and PDF/UA identification) and `{"fix": "parentTree"}` (rebuilds the tag links).

The assistant can call `a11y::check_doc` and `a11y::fix_doc` (and the `_doc` functions for reading order and tags: `reading_order_doc`, `tags_doc`, `reorder_doc`, `set_role_doc`, `artifact_doc`, `merge_doc`, `merge_many_doc`, `split_doc`, `edit_tag_doc`, `move_tag_doc`) with its own `EditSource`.

## The UI

`src/lib/a11yLogic.ts` (pure decisions, tested), `src/lib/a11y.ts` (store and commands), `src/components/a11y/A11yPanel.tsx`. It opens from Tools > Check accessibility... and the palette ("Check accessibility..."), as a right rail like Redact and Comments (opening one closes the others). The rail shows the result line with a segmented bar, the rules under Acrobat's seven groups (failed first), per failed rule its explanation, what Fix will do, the findings with their pages, and the buttons Fix and Show. Show jumps to the page above the element and outlines it (a pulsing outline in the page space, `PageView`'s `a11y` prop). A failed Figures alternate text finding has the figure's thumbnail (cut from a render of the page) and an alt-text field: Save is one undo step. The footer's "Fix all safe issues (n)" is one step and says what it will leave: "Fix 3 issues · after this 12 of 15 pass". The report is read again after every change of the document (a fix, undo, an edit), and a newer check stops the one still running. Cancel on an automatic check leaves it cancelled for that revision (a cancelled or failed check is started again only by Check again, by opening the rail, or by the next edit), and a report that no longer matches the document disables Fix, Fix all and the alt-text field until it is read again. On an untagged document a card at the top offers "Autotag (best effort)" with its outcome ("Adds tags to 12 pages; reading order from layout. 2 images get a Figure tag without alternate text. One undo step."), progress and Cancel. "Export report" asks where to save (HTML or PDF).

### Reading order, Tags and Matterhorn views

The rail has four views, a tab strip under its title: **Check** (the groups above), **Matterhorn**, **Reading order** and **Tags**. The tools catalog and the palette open the rail on a view ("Reading order", "Tags", "Matterhorn results"). The arrow keys move between the tabs. Logic is in `src/lib/a11yDepthLogic.ts` (pure, tested in `a11yDepth.test.ts`), state in `src/lib/a11y.ts`, components in `src/components/a11y/` (`OrderTool`, `OrderLayer`, `TagsTree`). Every edit goes through the edit lane (`lib/edit.ts` `run`), is one undo step, and holds the document the way a fix does; the view is read again after it, and a refusal is shown with the view snapped back to what the engine has.

- **Reading order.** Follows the page in view (`a11y_reading_order`). The page shows every region as a box with its number; the side list shows the same regions (number, type, start of text). Reorder: drag a number onto another region (it takes that region's place), or select a row (or a number on the page) and press Alt+Up or Alt+Down, or use Earlier and Later. Merge: select two or more regions next to each other in the list (Shift+click, Shift+arrow, Ctrl/Cmd+click) and press Merge; the first one keeps its type. Split: pick which content item the new region starts at. Artifact: takes the content out of the reading order. Regions written inside their parent (object number 0) are listed and numbered but can't be moved, merged, split or made an artifact. "Reads as" shows the page's text in the current order as a screen reader would say it (a heading says "Heading 2:", a figure without alternate text says "Figure, no description."); it refreshes after each edit. Content in no tag (`orphans`) is counted under the list.
- **Tags.** The tree from `a11y_tags`, windowed (28 px rows, only the rows in view and the children of expanded nodes are drawn); the top level opens by itself. A document of more than 100 pages starts with the current page's branches (one IPC reply carries the whole tree otherwise); "Show" switches. A row shows the type (and "as P" when it is mapped), the alternate text, the number of kids when closed, and a red mark when `a11y_tag_problems` names it; with problems a card offers "Repair links" (`{"fix": "parentTree"}`). Selecting a tag jumps to its content and outlines it (the box is the union of its regions' boxes on its first page; no box, a page jump). The editor under the tree sets type (`a11y_set_role`), alternate text, actual text, language, a header cell's scope and the header cells a cell is read with (`a11y_edit_tag`, only what changed is sent), and moves the tag up, down, into the tag above or out of its parent (`a11y_move_tag`). Keys: arrows to walk, Alt+Up/Down to move, Alt+Right/Left to put into or take out of the parent.
- **Matterhorn.** The report's rules are placed under the 31 checkpoints of the Matterhorn Protocol 1.1 by rule id (`RULE_CHECKPOINT` in `a11yDepthLogic.ts`; the report itself has no checkpoint field). A checkpoint shows its number and title, its state (the worst of its rules: failed, to check, passed, skipped), the count of findings of its failed rules ("... and n more" is counted), and the failure conditions its rules decide. Failed ones open; each rule inside keeps its explanation, findings, Show and Fix, as in the Check view. Checkpoints no rule decides are listed at the bottom as having no automatic check. `bookmarks` and `parent-tree` have no numbered condition and sit under "Other checks". Checkpoint numbers and titles are the protocol's own contents list (read from two published copies of the 1.1 text); the condition ids per rule are from the same text and only the ones the rule clearly decides are shown. `metadata` and `parent-tree` fixes (which the engine has) now get their Fix button too.

Checked end to end on copies of `docs/study` samples with `scripts/a11y-shots.mjs` (untagged, Autotag, check, alt text, Fix all, undo, save, reopen, report export, 1200 pages). Screens are in `docs/screens/a11y/`.

`tagged-pdf` also fails when `MarkInfo /Suspects` is true, and `heading-nesting` also fails when an unnumbered `H` is used together with `H1`-`H6`.

On an untagged document the structure rules (`figure-alt-text`, `reading-order`, `table-headers`, `heading-nesting`, `list-structure`, `content-marking`, `role-map`, `table-structure`, `table-scope`, `annotations-tagged`, `parent-tree`) are `skipped`, and `tagged-pdf` fails.

`reading-order` can't tell whether a difference is wrong, because content order isn't always reading order. A failure means "look at it": the hint says so.

## Reading order and tags

Engine: `a11y/order.rs` (what is on the page), `a11y/tags.rs` (the tree and its edits). Acrobat's Reading order tool and Tags panel.

`a11y_reading_order(doc, page) -> {page, tagged, regions, orphans}` lists the regions of a page in the order a screen reader reads them. A region is a structure element that holds marked content (or an annotation) on the page; the list is in tree order. Each region has `xref` (the object number every edit takes), `role` (standard type after the role map), `rawRole`, `depth`, `parent` (object number, 0 at the top), `mcids`, `annots`, `bbox` (`[x0, y0, x1, y1]` in points from the top left; text has a real extent, from the font's widths), `text` (preview, up to 120 characters, from ToUnicode or the simple font's codes), `alt` and `editable` (false for an element written directly inside its parent: it has no object number). `orphans` is marked content no element points at (nothing reads it). It reads the document as it is now, unsaved edits included, from its own copy like the check.

`a11y_tags(doc, page?) -> TagNode[]` is the tree, nested: `xref`, `role`, `rawRole`, `page`, `alt`, `actualText`, `lang`, `id`, `scope` (Row, Column, Both), `headers` (object numbers of the TH cells a cell lists), `mcids`, `annots`, `editable`, `children`. With `page`, only the branches that hold content there.

Edits (all one undo step, label in history; a change that would do nothing is refused and adds no step):

| command | does |
| --- | --- |
| `a11y_reorder(doc, page, order)` | `order` lists every region of the page once, in the order to read them. The regions that already read in the right order relative to each other stay; each other region is moved, with its kids, next to the one that should come before it. Refused when the order can't be made by moving whole elements (one region holds another). |
| `a11y_set_role(doc, xref, role)` | P, H1-H6, Figure, Table, L, LI, ... any standard type or a type in the RoleMap. `Artifact` is the same edit as `a11y_artifact`. The content stream's own tag name (`/P <</MCID 0>> BDC`) is left as written. |
| `a11y_artifact(doc, xref)` | the element and its kids leave the tree; each `BDC` of their MCIDs becomes `/Artifact BMC`; annotations lose `/StructParent`; the ParentTree forgets them. The text stays on the page. Parents left without kids stay (the list-structure rule then says so). |
| `a11y_merge_regions(doc, into, from)` | `from`'s content and kids move into `into` (before its own if `from` comes first in the tree, after otherwise); a bare MCID from another page becomes an MCR with `/Pg`. `into` keeps its role and attributes. |
| `a11y_merge_many(doc, into, from[])` | the same merge for several regions, in the order given, as one undo step; a refusal part way leaves the document as it was (up to 100 regions, `into` included: each merge reads the tree again). The Reading order tool uses this one. |
| `a11y_split_region(doc, xref, atMcid, role?)` | the content item with `atMcid` and everything after it in the element's kids move into a new sibling after it (same role unless `role`). |
| `a11y_edit_tag(doc, xref, {role?, alt?, actualText?, lang?, scope?, headers?})` | a field left out stays; an empty text removes it. `scope` only on TH. `headers` is a list of TH object numbers; they get an `/ID` if they have none, and the cell's table attributes (`/A` with `/O /Table`, made or extended; other attribute sets are kept) list the IDs. |
| `a11y_move_tag(doc, xref, parent, anchor?, after)` | `parent` 0 is the top of the tree. The place is named by a kid of `parent`: before `anchor`, or after it with `after`; without an anchor the node becomes the last kid. The engine finds the place in the raw `/K`, where content items sit between the elements, so mixed parents work. A move that leaves the node where it is is refused (no step). Not into itself or its own kids. Elements that relied on an inherited `/Pg` get their own, so content doesn't change page. |

Every edit that changes which element holds content updates both sides of the link: the element's `/K` and the ParentTree. The ParentTree is rewritten as one flat `/Nums` array (a tree in `/Kids` form is read, and flattened when an edit has to change it); `/ParentTreeNextKey` is raised. `a11y_tag_problems(doc)` returns where the tree and the ParentTree disagree (`tags::problems`, the same list the `parent-tree` rule reports); the tests assert it is empty after every edit, and `{"fix": "parentTree"}` rebuilds the links.

Signed and certified documents: every write of this module (`fix_doc`, `reorder_doc`, `set_role_doc`, `artifact_doc`, `merge_doc`, `merge_many_doc`, `split_doc`, `edit_tag_doc`, `move_tag_doc`) goes through `edit_doc`, which refuses a certified document (any `/DocMDP`, `/P` 1 to 3) with "This document is certified..." before reading anything, and never makes a rewriting step, so a signed document's save stays incremental and its signed bytes are the start of the saved file. `a11y_protection(doc) -> {certified, signed}` reads it from the document itself (the rail asks on open, so the controls are off before the first check ends; unknown counts as locked), and `Report.certified`/`Report.signed` repeat it: on a certified document every edit control is disabled with the reason, on a signed one a note says the edits are saved after the signed part. `apply_fix`/`apply_fix_with` are not guarded themselves: the Preflight conversion calls them, and `preflight::fix::apply` refuses an in-place conversion (`convert_in_place`, the rule Fix) of a certified or signed document, since that save is a full rewrite; converting into a new file is unaffected.

Guards: the tree reader drops a marked-content id outside `0..=1,000,000`, content with no page, an element reachable twice, and anything past depth 256 or 500,000 elements, and records that it did (`Tree::incomplete`). On such a tree every edit and the repair refuse (they would write what they didn't read) and `a11y_tag_problems` says why. The ParentTree is read the same way: entries that can't be kept (a key that isn't an integer, a value that is neither array nor reference, a repeated key) make edits refuse, and a rewritten ParentTree holds at most 4,000,000 entries. ToUnicode maps are read up to 4 MB and 70,000 entries.

Reorder keeps table and list structure: a region may move under another parent only if the new parent takes it (TD/TH only in TR, TR only in Table/THead/TBody/TFoot, LI only in L, Lbl/LBody only in LI, and those parents take only their own parts). It refuses a move that would change the order on another page the moved region also holds content on, and checks the page's order again after the moves.

Content drawn by a form XObject (an MCR with `/Stm`, keyed on the stream's `/StructParents`) is checked by `parent-tree`, followed by merge, split and repair, and kept by move; it isn't listed in the reading order, and mark as artifact refuses an element that has any. Merging a header cell keeps `/Headers` working: the surviving cell takes the merged cell's `/ID`, or the cells that named it are updated.

Limits: an element with both content and child elements is listed once, at its first content; a region whose parent is a direct dictionary can't be moved; Artifact can't be undone by role change (undo the step instead); marking an inner MCID as artifact inside tagged content leaves an artifact in tagged content, which `content-marking` then reports.

## Autotag (best effort)

Autotag runs only on untagged documents and is labelled "Autotag (best effort)" in the undo menu and history. It reads MuPDF structured text and builds Document > blocks:

- **Headings**: blocks of at most 3 lines and 200 characters, set at least 1.15x the body size. The body size is the size most characters use. Heading sizes, largest first, become H1 to H6.
- **Lists**: blocks whose first line starts with a bullet, a dash or `1.`, `a)`, `iv.`. They become L > LI > LBody, with a new item at each line that has a marker.
- **Paragraphs**: every other block becomes P.
- **Tables**: a run of rows whose cells line up becomes Table > TR > TH/TD (`a11y/tables.rs`, structured text only). A cell is one structured-text line and a row is the lines whose baselines are within 2 pt; a column is the cell at one position in every row, with left edges, right edges or centers within 4 pt (the header row may sit differently over its column), and neighbouring columns must not overlap. Every row must have the same number of cells and be drawn after the row above it (cells drawn column by column would read in another order than they are drawn). The first row is TH with `Scope Column` when it is bold or at least 1.1x larger than the rows below, or has a ruling line under it across two columns; otherwise all cells are TD, and the checker's `table-headers` then asks for a header, which the Tags panel can set. A table needs at least 2 rows and 2 columns and something to confirm it: a header row that differs, or a ruling line across two columns near its rows (stroked lines, thin filled rectangles, stroked rectangle edges, which stay `/Artifact`), or else at least 3 rows and 3 columns. It is not a table when the cells read as prose (6 or more words a cell on average, or 4 and sentence endings), when a column is only list markers, when 40% or more of the cells end in a colon (a form), or when a form field lies on it. At most 300 rows by 16 columns a table and 6,000 text lines a page; beyond that the page keeps paragraphs.
  - Irregular tables stay paragraphs: a row with a missing or merged cell between rows that have cells, a spanning row, or a cell that wraps onto a second line. Autotag does not set RowSpan or ColSpan, because it cannot tell a merged cell from a missing one with certainty; the Tags panel edits them. Rows before or after the table that have one cell (a title, a footnote) are not part of it.
- **Figures**: images (XObject or inline) become Figure, with no alternate text, so the checker then asks for it. They are placed before the first block below them.
- **Text in form XObjects**: a form with text becomes P. A form without text is marked as an artifact.
- **Annotations**: Link and Widget annotations become Link and Form elements with an OBJR and `/StructParent`.
- **Everything else**: other painting (paths, shadings) is marked `/Artifact`.

The content streams are rewritten only by inserting `BDC`/`BMC` ... `EMC` at operator boundaries, one MCID per run of text on one structured-text line. Nothing is moved or redrawn. A run that would start before the previous one ends (invalid content, such as a path left open across a text object) is left unmarked. The test checks that the page renders to the same PNG and extracts the same text before and after. The parent tree, `StructParents`/`StructParent`, `ParentTreeNextKey` and `MarkInfo` are written.

## Gaps

- **Autotag**:
  - Tables only when regular: no merged or empty cells, no cells of two or more lines, no tables drawn column by column; those stay paragraphs.
  - No Lbl/LBody split inside an item.
  - No TOC, captions, notes or language spans.
  - Multi-column order is MuPDF's block order.
  - Text that is already inside marked content (for example optional content `/OC` BDC) is left untagged.
  - Text inside form XObjects is tagged as one P around the `Do`, not line by line.
  - Text that lands on no structured-text line goes into one P at the end of the page.
- **Checker**:
  - Not covered: image-only pages, multimedia, table summary, nested or hidden alt text, and Acrobat's other manual checks (flicker, scripts, timed responses, navigation links). The Matterhorn table above lists the machine-checkable conditions not implemented yet (Formula alt text, Note ids, embedded file specifications, reference and PostScript XObjects, font program details).
  - pdfcraft has these in `crates/a11y` if they are wanted.
  - MCIDs inside form XObjects (`/Stm`) are not compared for reading order.
  - The title check reads only Info `/Title`, not XMP `dc:title`. The title fix doesn't update the XMP metadata either.
- **Reading order and Tags UI**: the reading order text preview is the first 120 characters of each region (the engine's `text`); `a11y_preview` is Autotag's outcome, not a text preview. Orphan content (in no tag) is listed but there is no command to attach it to a region. A split can only say which content item (k of n), because a region carries no per-item text or box. The tag tree is one reply for the whole document (a 500,000-element tree is a large message); only the drawing is lazy. Moving a tag into a tag with no object number is not offered.
- **UI**: "Show" has no outline for text-only elements (page jump only). The Primary language fix uses the language picked in the rail, never the document's text. "Passed manually" / "Failed manually" and "Skip rule" from Acrobat are not offered.

## Building on Linux

`cargo test --lib a11y` needs `libgtk-3-dev`, `libwebkit2gtk-4.1-dev` and `LIBCLANG_PATH`. The `history/` module calls Windows APIs unconditionally (`std::os::windows`, `windows_sys`), so the lib doesn't compile on Linux unless those functions get non-Windows stubs. The cloud run used local, uncommitted stubs.
