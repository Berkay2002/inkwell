# Fill & Sign and digital signatures

Engine: `src-tauri/src/sign/`. `pdf.rs` writes and checks PAdES signatures, `crypto/` has the CMS, X.509, PKCS#12 and key code and the Windows certificate store and trust (`trust.rs`, `winstore.rs`), `app.rs` has the commands. Tests are in `sign/tests.rs` and `sign/crypto/tests.rs`. They use two generated test IDs ("Maple Property" and "Alex"), never a real certificate. The UI is in `src/lib/sign.ts` (store and commands) and `src/components/sign/` (the Fill & Sign strip, the page layer and the Signatures rail).

## Commands

- `sign_identities` lists the IDs: Windows store certificates with a private key, ID files opened this session, and test IDs. An ID that can't sign is listed with the reason (`unusable`). The UI never pre-selects a Windows store ID: the user picks their own certificate.
- `sign_open_id_file` opens a `.pfx`/`.p12` file with its password. `sign_create_test_id` makes a self-signed test ID.
- `sign_document` signs as one incremental update (the bytes before it are kept as they are), optionally certifying (DocMDP P=1, 2 or 3), with a visible box or none.
- `sign_list` returns `certify`, the document's DocMDP level as signing reads it (`docmdp_level`: the strictest in the catalog's `/Perms` or any signature; one that can't be read is 1), and `signatures`: a `SignatureInfo` per signature field with `status` (`valid`, `unknownSigner`, `warning`, `invalid`, `unsigned`), `changes` (`none`, `signaturesOnly`, `changed`), the signer, issuer, the time from `/M`, the reason, the certify level, `warnings` with a stable `code`, `readOnly`, `lockedBy` (the signer whose lock covers the field) and, on an empty field, `refused`: the reason `sign_document` would refuse it with. Both come from one function (`pdf.rs` `refusal`), so the UI never guesses. When the signatures can't be checked (more than 64), `signatures` is empty, `certify` is still given (so a P=1 refusal keeps its reason) and `error` says why; the banner and the rail show that as invalid, never as an unsigned document.

## Signature fields on the page

A signature field in a form is a button over the field. An empty one (`<label>: click to sign`) opens the signing sheet aimed at that field (`signField`, the same entry as the Sign tool's "Sign here" and the rail's empty-field "Sign"); nothing is signed until Sign is pressed in the sheet. A signed one (`<label>: signed by <name>, click for details`) opens the Signatures rail on that signature. An empty field the engine refuses (`refused`) shows `<label>: <reason>` and does nothing (`aria-disabled`); the Sign tool shows "Can't sign" on it with the reason as its title, and the rail lists the reason in place of Sign. The engine refuses an empty field when:

- the document is certified with no changes allowed (P=1, or a certification that can't be read); P=2 and P=3 allow signing;
- the field is read-only (`Ff` bit 1, on the widget or inherited through `/Parent`; a looping chain stops at the first object seen twice or 64 levels; an `/Ff` that is not a number counts as read-only);
- an earlier signature locks it: "Field X is locked by <signer>'s signature."

## Field locks (FieldMDP)

A signature locks fields through its field's `/Lock` (ISO 32000-1 12.7.5.5) and its `/Reference` entries with `/TransformMethod /FieldMDP` (12.8.2.4), which name them the same way: `/Action /All`, `/Include` or `/Exclude` with `/Fields`, an array of full field names. A name also covers the fields below it (`a` covers `a.b`). Names in `/Fields` are full names only: a partial name (`b` for `a.b`) matches nothing. A field name over 1024 bytes or with more than 64 dots counts as locked whenever any lock exists (looking it up level by level would cost too much). The reader is shared with form scripts (`forms/scripts.rs` `signature_locks`). Anything it can't read locks every field: an unknown `/Action` (read as `/All`), a `/Lock` that isn't a dictionary, an `/Include` without `/Fields`, with `/Fields` not an array, with an entry that isn't text (a lone UTF-16 surrogate included) or with more than 4096 names, a `/Reference` that is neither an array nor a dictionary, has more than 16 entries or an entry without a readable method. A DocMDP P=1 reference locks everything too. A PDF 2.0 `/Lock /P` (ISO 32000-2 12.7.5.5) on a signed field, now or in the revision it signs, is a document-level DocMDP level like a certification's: the lowest of them and the certification's is the level `sign_list` reports as `certify` and signing refuses by (P=1 refuses every signature). A `/P` that isn't a number counts as 1. Only signed fields lock; a `/Lock` on an empty field is a promise for later and locks nothing yet. Every signed field counts, even one whose signature is invalid or forged (the safe side). A signature's locks are read from the field now and from the revision it signs (the field holding the same signature dictionary there), so a later update can't strip or rename them away; when that revision can't be read, or has no field holding the signature, the signature locks every field. A signature that isn't intact locks every field, wherever its `/ByteRange` ends (a later update may have stripped its locks and pointed the range at itself); an intact one covering the whole file is read from the file as it is. Such a signature (not intact, or its revision unreadable) also counts as `/P` 1: what it allowed is unknown, so the document reads as allowing no changes and signing it is refused, a new box included. A signature removed altogether by a later update (its `/V` or its field) is not seen and locks nothing. A lock covers the fields there when it signed (ISO 32000-1 12.8.2.4); adding fields is DocMDP's call. So a new signature box is allowed under `/All` and `/Exclude`, and takes the first `SignatureN` that no form field has and no `/Include` names (`/Include [Signature2]` skips to `Signature3`). `lockedChanged` only compares fields that were there when it signed, so a new box doesn't flag. Signing refuses a file with more than 64 signatures, as checking does.

When a later update changes the `/V` or any widget's `/AP` of a field an intact signature locked (read from the revision it signs, by full name; a removed field or another widget under its name counts), that signature gets the `lockedChanged` warning naming up to three fields. The comparison spends at most 100,000 object nodes per revision; past that it reads as "the form" changed. It compares `/V` and `/AP` only: a change to `/Rect`, `/F`, `/Ff`, `/Opt` or `/DA` shows only as `changed`, and an appearance rewritten under a new object number reads as changed even when it draws the same. The status follows the usual rules (`warning` when trusted), on top of `changed` or `signaturesOnly`.

## How a signature is checked

1. **Byte range.** `/ByteRange` must start at 0, leave exactly the `/Contents` hex string out, and stay inside the file. The signature covers the file up to the range's end.
2. **CMS.** The digest of the covered bytes must match the signed attributes, and the signature over the attributes must verify with the signer's key. SHA-1 gives a `sha1` warning.
3. **Trust.** The signer's chain is built by Windows (`CertGetCertificateChain`, local caches only, so no network) at the signing time, and must allow document signing or email protection. A self-signed, unknown, expired or wrong-usage signer is `unknownSigner`; the signature can still be intact.
4. **Bound to its revision.** The signature dictionary and the field it fills must be the same objects, unchanged, in the revision the signature covers (that revision is parsed on its own). This stops a signature being moved to another field or dictionary in a later update.
5. **What came after.** When the signature doesn't cover the whole file, each later update is judged on its own: it is "signatures only" if it adds nothing but signatures that themselves verify and end that update. That means their dictionaries, widgets and fields (from a fixed list of keys, no actions), their appearances and the images those name, the page's `/Annots` and the form's `/Fields` gaining exactly those, and unreferenced object or cross-reference streams. The trailer must be the same except `/Prev`, `/Size`, `/ID` and `/XRefStm` (and, when the update ends in a cross-reference stream, that stream's own keys), and no trailer or cross-reference stream dictionary may name a key twice (MuPDF keeps the last, other readers the first). The update must be exactly one cross-reference section, in its own bytes, whose `/Prev` is the signed revision's (MuPDF follows the whole `/Prev` chain, so a second section could list objects nothing else checks). Its `/Size` must be at least the signed revision's and past every number it lists (a strict reader takes numbers past `/Size` as missing), and a cross-reference stream must be unfiltered or Flate (plain, or with the PNG predictor over rows of `/W`'s width). A hybrid section's `/XRefStm` stream may be listed by the classic table instead of itself, as Word writes it, but a cross-reference stream is only read when the newest listing of its number (in the sections read before it) is that stream at that offset: MuPDF reads the stream by offset, so a newer section naming the number elsewhere is a decoy and the chain reads as changed. Every entry it lists is checked, and a number listed twice is a change: an object at an offset must be written there under the same number and generation, and one placed in an object stream must be at the index named, in a stream that lists no number twice (MuPDF takes the first copy of a number, other readers the index). A number the signed revision used keeps its generation, read from every section along the signed revision's `/Prev` chain and a hybrid section's `/XRefStm`; a used number none of them lists is a change. MuPDF ignores generations, other readers resolve the old reference to nothing. Anything else is `changed`.
6. **Later boxes.** Any signature widget added after this signature that draws on the page (whether or not that later signature verifies; NoView with Print still prints, so it counts) gives `laterBox`, or `laterBoxLarge` past a quarter of the page: it can paint over what was signed.
7. **Damage.** If MuPDF had to repair the file to read it, or a later update names a second cross-reference table (`/XRefStm`, in any trailer, escaped names included), other readers may show a different file: the signature's changes are `changed`, with a `damaged` or `hybridXref` warning.
8. **Certification.** A certifying signature (DocMDP) with P=1 and any change after it is `invalid`. With P=2 or P=3 a change is a warning that says what the certification allows (form filling; P=3 also comments), since Inkwell can't tell those apart from other changes.

Limits on work: at most 64 signatures in a file, 64 revisions after a signature, and object graphs compared to 10,000 nodes and 64 levels. A file past those is refused or reads as `changed`, never as clean.

## Known limits

- **No timestamps.** An RFC 3161 timestamp token is not checked; the time shown is `/M`, the signer's own clock ("per the signer's clock" in the rail).
- **No revocation.** CRLs and OCSP are not fetched or read (also not from `/DSS`), so a revoked certificate still reads as trusted.
- **Form fill and comments are not told apart.** Any change other than further signatures is `changed`, including a form fill a P=2 certification allows.
- **Adobe's own additions read as changed.** Acrobat adds `/DR`, `/DSS` and appearance updates when it signs again or adds long-term validation; Inkwell reports those as changes.
- **A broken field lock is a warning, not invalid.** A change to a locked field is reported on the locking signature, as a P=2 change is; Inkwell does not call the signature invalid for it.
- **No content-overlap check.** A later box is flagged by its size, not by whether it covers anything signed.
- **`/Lock /P` only gates signing.** The level from a field's `/Lock /P`, and the P=1 a broken signature counts as, are read by `sign` and `sign_list` (and the UI's lock), not by `outline::certified`, which every other editing feature asks before writing. Folding them in there would need the signature fields and their signed revisions (it reads only the `/V` values of `/AcroForm /Fields`), and would make every edit feature refuse a document with a broken signature; that is left for a separate change. So bookmarks, comments and the like can still be added to such a file.
- **One reader's view.** The check reads the file with MuPDF and closes the gaps known where other readers differ (repair, hybrid tables, object stream indexes), but cannot prove every reader shows the same page.
